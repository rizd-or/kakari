# Ensemble Rizd’or 係決めシステム

係決め会議で使うWebサイトです。毎年の選管に引き継いで使います。

- **本番・係決め**：希望を見ながら配属を決める（ドラッグ＆ドロップ／クリック）
- **シミュレーション**：案A・案B…を作って比べる。本番には影響しない
- **係説明**：各係の仕事内容。パスワードなしで誰でも見られる
- **設定（右上の歯車）**：CSV読み込み、係・定員、兼任ルール、メンバー、バックアップ、期の切り替え（60期→61期など）

選管ログインすると本番の編集とシミュレーションが使えます。ログインしていない人は「本番の配属先（希望順位は非表示）」と「係説明」だけ見られます。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `index.html` | サイト本体 |
| `config.js` | 接続先（Apps ScriptのURL）を書くファイル |
| `gas/Code.gs` | データをGoogleスプレッドシートに保存するためのプログラム（パスワードが書かれているのでGitHubには上げない） |
| `sample.csv` | 動作確認用のダミー回答（実在の人ではありません） |

データの保存先は2通りあります。

- `config.js`（または `index.html`）の `GAS_URL` が**空**のとき：開いたPCのブラウザの中だけに保存（お試し用）
- `GAS_URL` を**設定**したとき：Googleスプレッドシートに保存。どのPCで開いても同じ内容になる

## はじめての設置（1回だけ・30分ほど）

### 1. 保存用スプレッドシートを作る

1. サークルのGoogleアカウントで新しいスプレッドシートを作る（名前は「係決めデータ」など）
2. メニューの「拡張機能」→「Apps Script」を開く
3. 最初からある `コード.gs` の中身を全部消し、`gas/Code.gs` の中身を貼り付けて保存
4. 選管ログインのパスワードは、`Code.gs` の `DEFAULT_PASS` に書かれているものになります（変えたいときは `setPasscode` の `PASS` を書き換えて「▷ 実行」）
5. 上の関数選択で `doGet` を選んで一度「▷ 実行」し、許可を求められたら許可する

### 2. ウェブアプリとして公開する

1. 右上の「デプロイ」→「新しいデプロイ」（**最初の1回だけ**。2回目以降は「デプロイを管理」から更新）
2. 種類は「ウェブアプリ」
3. 「次のユーザーとして実行」：**自分**
4. 「アクセスできるユーザー」：**全員**
5. 「デプロイ」→ 表示された **ウェブアプリのURL**（`https://script.google.com/macros/s/…/exec`）をコピー

> パスワードなしで返すのは「係説明」と「本番の配属先（名前・あだ名・配属された係）」だけです。希望順位・兼任の希望・属性・メモ・シミュレーション・変更履歴は、選管ログインしないと見られません。
> 初回の許可で「このアプリは Google で確認されていません」と出たら、「詳細」→「（プロジェクト名）（安全ではないページ）に移動」で進めます。自分で作ったスクリプトなので問題ありません。

### 3. サイトにURLを書き込む

`config.js` をメモ帳で開いて、`""` の中にURLを貼ります。

```js
window.RIZDOR_CONFIG = {
  GAS_URL: "https://script.google.com/macros/s/xxxxxxxx/exec"
};
```

`config.js` は `index.html` と同じ場所（GitHubのリポジトリのいちばん上）に置きます。ここに書いておけば、`index.html` を新しい版に差し替えても書き直す必要はありません。
（`index.html` の `GAS_URL` に直接書いても動きます。両方あるときは `index.html` が優先です）

### 4. GitHub Pagesで公開する

1. GitHubで新しいリポジトリを作る（例：`rizdor-kakari`。Publicで可）
2. `index.html` をアップロード（「Add file」→「Upload files」）
3. 「Settings」→「Pages」→ Branch を `main`、フォルダを `/ (root)` にして Save
4. 数分後に `https://<ユーザー名>.github.io/rizdor-kakari/` で開けるようになる

以後、GitHub上で `index.html` を編集して保存（Commit）すると、数分でサイトに自動で反映されます。

> GitHubに上げるのは `index.html` と `config.js`（と `README.md`）だけにしてください。`gas/Code.gs` にはパスワードが書かれています。実際の回答CSVもアップロードしないでください。

## 毎年の使い方

### 1. 新しい期を始める（前の期の結果が残っている場合）

設定 →「バックアップ・期」→「新しい期を始める」（60期の次は自動で61期になります）。
係・定員・ルール・係説明はそのまま残り、メンバーと配属だけ空になります。前の期の結果は「過去の期」に保存され、各係の「前の期の人数」も自動で入ります。

### 2. 係・定員・説明を見直す

- 定員・必要な条件：設定 →「係・定員」
- 兼任の注意：設定 →「兼任ルール」
- 説明文：「係説明」画面の各係の「編集」

### 3. Googleフォームを作る

おすすめの形は次の通りです。

- 「名前」「あだ名」の質問
- 「第1希望」「第2希望」…「第5希望」の5つの質問（プルダウン。選択肢は係名と同じにする）
- 「早稲田生ですか？」「運転免許を持っていますか？」（はい／いいえ）
- 「第何志望までであれば兼任を考えていますか？」（兼任を考えていない／第2志望〜第5志望）
- 「兼任を何個考えていますか？」（1つ〜5つ。担当する係の合計数として扱います）
  - この2問の回答がない人には、自動配属で兼任を入れません

係ごとに順位を選ぶ「選択式（グリッド）」の形でも読み込めます。

### 4. 回答を読み込む

フォームの「回答」タブ → ︙ →「回答をダウンロード（.csv）」。
サイトの 設定 →「CSV読み込み」でそのファイルを選びます。列の対応づけとプレビューを確認してから読み込んでください。

- 同じ名前で2回答えた人は、新しい回答が使われます
- 係名と一致しない答えは、プレビューで警告が出ます
- あとから回答が増えた場合は「名前で照合して更新」を使うと、今の配属を残したまま希望を更新できます

### 5. 係決め当日

- 右上の「選管ログイン」からパスワードを入力
- 左の一覧からメンバーをクリックすると、各係に「第何希望か」「配属後の人数」「警告」が出ます
- 「＋配属」かドラッグ＆ドロップで配属。係から係へドラッグすると移動、左の一覧に戻すと解除
- 間違えたら「元に戻す」（Ctrl+Z）
- 「✨ 自動配属」で2つの方法から選べます。適用する前に、結果と今の配属との違いを確認できます
  - **志望順に1段ずつ**：第1志望の分だけ入れる → 話し合う → 第2志望の分…と段階的に入れる
  - **AI配属**：条件（兼任の扱い・最低人数・必要条件・兼任非推奨・希望外を認めるか・男女バランス）を選ぶと、全員の希望ができるだけかなう配属を自動で探して一気に入れる。「🎲 別の案を出す」で別の組み合わせも見られる。第1希望に入れなかった人とその理由も表示される
  - 今の配属があるときは「残して追加」か「消して最初から配属し直す」かを選べます
- 「⤺ 一括配属を取り消す」：自動配属で入れた分だけを、新しいものから順に取り消します（手で入れた配属・CSVの読み込みはそのまま）
- 「リセット」：配属をすべて外します（メンバーと希望は残ります。「元に戻す」で戻せます）
- 選管ログイン中は、係ごと・全体の**男女比**が表示されます（フォームに「性別」の質問があればCSVから読み込み。メンバーを選んで手で入れることもできます）
- 各係の**前の期の人数**（例：59期 5人）が参考として表示されます（設定 →「係・定員」で入力。新しい期を始めると自動で入ります）
- 終わったら「結果を確定」→「出力・印刷」でCSVやPDFに出力

## 困ったとき

| 症状 | 対処 |
|---|---|
| 右上に「保存エラー」「オフライン」と出る | 通信が戻れば自動で再保存されます。データはそのPCにも一時保存されています |
| 「ほかのPCで内容が更新されています」と出る | 基本は1台で操作してください。どちらを残すか選べます |
| 間違えて消した | 設定 →「バックアップ・期」の自動スナップショットから戻す |
| もっと前の状態に戻したい | スプレッドシートの `_backup` シートの行番号を確認し、Apps Script の `restoreFromBackup` で戻す |
| パスワードを変えたい | Apps Script の `setPasscode` の `PASS` を書き換えて実行する。スプレッドシート未設定で使っている場合は、`index.html` の `PASS_HASH` も変える（新しいパスワードのSHA-256） |
| GitHubで直したのに変わらない | 反映に数分〜10分かかります。サイトのURLの最後に `?v=数字` を付けて開くとすぐ確認できます |
| ログインできない（サーバーにつながりません） | ⚙ →「全般」で接続先URLを確認。Apps Script のURLの最後に `?key=パスワード` を付けて開き、`"authed":true` と出ればサーバーは正常です |
| 「新しいデプロイ」をしてしまった | URLが変わっています。新しいURLを `index.html` の `GAS_URL` に入れ直してください |
| Apps Script を書き換えた | 「デプロイ」→「デプロイを管理」→ 鉛筆マーク →「新バージョン」で更新（URLは変わりません） |

## プログラムを直したい人へ

- サイトは `index.html` の1ファイルだけです（ビルド不要・外部ライブラリなし）
- 係の初期値は `defaultRoles()` にありますが、ふだんは設定画面から変えれば十分です
- データはJSON1つにまとまっていて、構造は `defaultState()` を見るとわかります
